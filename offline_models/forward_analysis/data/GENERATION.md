### 1. The Core Misunderstanding: Pure-LLM Synthetic Data Generation

You want to eliminate the local execution step entirely: **no local forward passes, no C++ engines running toy problems, and no synthetic script math.**

Instead, a frontier LLM (the teacher) imagines a realistic real-world scenario (e.g., medical diagnostics, financial risk modeling, sensor failure telemetry), hallucinates a complete network architecture with plausible $N$-dimensional inputs, layer-by-layer activations, predictions, and errors, and writes an expert structural analysis explaining how those internal activations behave.

```
┌────────────────────────────────────────────────────────────────────────┐
│                      PURE FRONTIER LLM SYNTHESIZER                     │
│                                                                        │
│  1. Hallucinates a realistic real-world problem domain                 │
│  2. Hallucinates the N-D input vectors, activations, and errors        │
│  3. Analyzes how the layers, paths, and representations behave         │
│  4. Emits the complete, self-contained training sample JSON            │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│                   LOCAL DISTILLER MODEL TRAINING                       │
│                                                                        │
│  • Ingests the hallucinated multidimensional float arrays              │
│  • Learns to predict the expert behavioral analysis text              │
│  • Zero runtime forward execution needed on your machine               │
└────────────────────────────────────────────────────────────────────────┘

```

The distiller does not care whether the numbers were calculated by BLAS matrix routines or generated by an LLM; it only learns the cross-attention mapping from continuous float tensors to qualitative structural concepts.

### 4. How to Use This in Your Training Loop

1. **Dataset Generation:** Run an automated script calling the prompt above to create 500 to 2,000 JSONL records. You do not need to compile or run C++ or Python networks for this stage.
2. **Importing into the Distiller:** Ingest `inputs`, `layer_activations`, `predictions`, and `residuals` from the JSON directly into your native buffers (`ForwardTelemetryTensor` / `Eigen::MatrixXd`).


3. **Training Objective:** Train your encoder-decoder bridge to map those float arrays to the four qualitative fields in `ground_truth_target_text`.


# TASK: Generate Pure-Token Synthetic Telemetry Dataset (NO SCRIPTS, NO TEMPLATES)

CRITICAL INSTRUCTION: 
DO NOT write a Python script. 
DO NOT write an algorithmic generator. 
DO NOT use string-formatting templates, lookup dictionaries, or Mad-Libs math.
You must directly output the synthetic training records as raw JSONL text tokens directly into the files.

---

### Strict Guidelines for Record Generation:
1. **NO DOMAIN NARRATIVES**: 
   - Exclude all medical, industrial, turbine, credit, or sensor jargon. 
   - All text and telemetry must describe purely mathematical, topological, and architectural properties of multi-dimensional vector transformations.
2. **GENUINE MULTI-DIMENSIONAL MATRICES**:
   - `input_dim`: Must vary between 6 and 16 dimensions per record.
   - `hidden_dims`: 1 to 2 hidden layers with widths between 8 and 24.
   - `output_dim`: 1 to 4 dimensions.
   - `batch_size` (rows $N$): 4 to 8 samples per record.
   - Floats rounded to 4 decimal places.
3. **GROUND-TRUTH QUALITATIVE DIAGNOSTICS**:
   - The LLM must analyze the interactions between the inputs, hidden activations, predictions, and targets.
   - Absolutely NO scalar repeating (no "mean is 0.28" or "accuracy is 80%").
   - Use structural, topological, and geometrical reasoning: describe hyperplane routing, half-space clipping, dormant coordinates, dynamic range attenuation, dominant singular axes, and subspace collapse.
4. **COVER DISTINCT MATHEMATICAL PATHOLOGIES**:
   Ensure the records represent diverse structural conditions:
   - Rank-1 / Subspace Collinearity (activations scale strictly along a 1D ray).
   - Severe Dead ReLU Corridor (40–70% of units permanently at 0.0 across the batch).
   - Half-Space Domain Clipping (activations drop to 0.0 whenever a specific coordinate $x_i < 0$).
   - Dynamic Range Attenuation (predictions track target signs but amplitude is heavily dampened).
   - Feature Axis Domination (hidden units respond only to 1 or 2 input coordinates).
